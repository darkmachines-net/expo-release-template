# Provider execution

`worker.mjs` is the fixed workflow entry point. `github.mjs` owns immutable plans, confirmed-operation receipts and retry reuse; a failed attempt never prevents a fresh release. Consumers supply metadata and validation hooks, without deployment/recovery wrappers.

`continuous.mjs` checks the beta promotion reviewer boundary before staging. `development.mjs` owns credential-free native inspection/export and separate authenticated EAS build/publication. `development-build.mjs` reconciles automatic clients against EAS by full native compatibility across commits, using an inert project for provider reads and asynchronous polling while cloud builds run. `development-history.mjs` records `expo-development-v1` deployment intents and confirmed provider links independently of release reservations. Only successful statuses advance per-platform native/bundle baselines. Same-attempt duplicate operations are rejected; retries reuse confirmed results. Automatic builds recover compatible EAS clients after a lost GitHub acknowledgement; an unconfirmed provider acknowledgement can still cause redundant delivery. The [consumer contract](consumer/README.md#continuous-delivery-to-beta) owns setup and tester instructions.

`deploy.mjs` supports the existing WireGuard webhook. `gcp.mjs` supports a provisioned Cloud Run API, optional private worker, migration job, Artifact Registry repository and Firebase Hosting site. Set `server.deployment.provider` to `gcp` with `project`, `region`, `api`, `migrationJob`, `hostingSite`, `registry`, and the public HTTPS `origin`. Add `worker` only when the application owns a separate worker service. Optional `readinessPath` selects an absolute path (default `/api/ready`); query strings, traversal, and foreign origins are rejected. Infrastructure and OAuth/store configuration remain with the application.

The protected deploy environment supplies `GCP_WORKLOAD_IDENTITY_PROVIDER` and `GCP_RELEASE_SERVICE_ACCOUNT`. Bind federation to the consumer repository, its protected default branch and that exact environment. The caller workflow must grant `id-token: write` as well as its existing permissions. The release identity needs registry write, Cloud Run deploy/job execution, service-account use for the three runtimes, and Firebase Hosting administration. It needs no database password or AI key. Artifact production and CLI installation finish before federation credentials are admitted.

Deployment consumes the confirmed GHCR publication digest, copies it without digest changes into Artifact Registry, runs the migration job, verifies startup probes and revision digests, and checks the staged API's readiness path. Each configured service receives a release tag with zero traffic before verification: Cloud Run otherwise leaves a worker revision retired when traffic is pinned to its predecessor. Worker tags retain the service's IAM restriction. Every readiness path must report `{status:"ok",version,revision}` for the deployed release and `K_REVISION`; a custom path never relaxes that contract. Only then does deployment switch traffic and publish Hosting with `pinTag:true`. Public HTTPS readback must match the same API revision. Native and OTA jobs remain gated on deployment success. API-only receipts omit `workerRevision`.

An uncertain deployment has no success receipt. A job retry may repeat those provider operations; migrations must be additive and idempotent. Confirmed entire operations are reused by `perform`. Databases are never rolled back automatically. Retain compatibility with older clients and rolling service revisions.

Container smoke configuration supports `services.<name>.ready` (a command run inside the dependency) and `initialize` (a command in the exact built application image, before API startup). These use an owned Docker network and disposable containers without publication credentials. No production migration is run during smoke validation.

## iOS store signing

`ios-signing.mjs` checks planned iOS cloud builds using the EAS CLI version pinned in `eas.mjs`. Its small internal-API adapter is covered by the installed-CLI contract tests on Windows and Linux. Source preparation introspects the selected profile's Expo config without credentials and saves the main app and extension entitlements in the immutable plan. APNs requirements use `production` for store signing, matching [Xcode's profile-derived entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/aps-environment) even when a config plugin emits `development`. The signing worker reads these values without installing or evaluating application code.

Assign an App Store Connect **team** API key with provisioning access to each iOS app's EAS credentials. A submission-only or individual key is insufficient. The worker uses the signing environment's `EXPO_TOKEN` and the assigned EAS key; no Apple key files are downloaded or passed into source hooks. The live check verifies project ownership, store-profile identity, certificate validity on Apple, expiry and required entitlements. It refreshes invalid/expired profiles with the existing distribution certificate and verifies the saved result. A profile removed by a previously interrupted regeneration can be replaced with the same certificate on a later attempt. Missing credentials, expired/revoked certificates, insufficient API permissions, or unsupported/missing Apple capabilities stop the release with an operator setup instruction. Certificates and capabilities are never rotated or changed by this check.

Signing readiness is not cached as a success receipt. Each executed signing job checks live state, and each new iOS build request checks again after reconciling accepted builds. Finished or pending builds for the exact run are reused without demanding fresh signing; they retain their original version/code reservations. The iOS build command allows EAS to refresh profiles again if their state changes between the check and enqueueing. Android credential freezing is unchanged. Provider errors do not trigger a second write within the invocation; an explicit retry re-reads provider state. OTA-only and server-only plans do not access signing credentials. The [workflow ordering contract](../.github/workflows/README.md#immutable-evidence-and-job-retries) owns deployment gating.
